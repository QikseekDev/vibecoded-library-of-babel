How it works: a page is a fixed-size grid of quantized pixels (or a fixed-length run of bytes holding any Unicode text at all — every script, symbol and emoji). Every possible pixel/character combination at that size already "exists" as a numbered page — uploading an image or typing text just computes which page number is an exact match, it doesn't invent anything new. The page number is then written down as compactly as possible: it is prediction-filtered and DEFLATE-compressed (all completely lossless — the page that comes back is bit-for-bit the page you located, at the resolution and colour depth you chose), then written in a 32768-symbol alphabet of whole Unicode characters at 15 bits per character instead of base64's 6, behind a varint header that only spends the bytes it needs, and — on the text shelf — at a page length trimmed to exactly fit your text so no padding is paid for. The tool tries nine different ways of writing each image address (raw, three predictor filters, channel-planar reordering, and an indexed-colour palette, each DEFLATE-compressed) and four ways for text, then keeps the shortest. Full 1440×2560 pages are supported, and a real photograph's address typically comes out several times shorter than its raw form without a single pixel changing. Shareable links carry the same bytes in a 76-symbol fragment-safe alphabet (~6.25 bits per character, shorter than base64's 6) in the URL fragment, which browsers never send to any server; non-ASCII characters would otherwise be percent-escaped to nine bytes each. The pointer also carries a tiny header recording its own resolution, colour depth, or length, so pasting a pointer alone is enough to reproduce the exact page — nothing else to set by hand, and nothing saved on any server. Almost all addresses, if you jump to one at random, are static — meaningful pages are a vanishing fraction of the space, same as the real Library of Babel.
